# 棒球數位孿生｜公開展示版

這是可公開分享的互動 3D 概念展示，依 **2026-09-28 開放感測器計畫**、**2026-09-29 價格查核 v3.1** 更新。與私人研發 repo 分離：只公開候選設備、工程預算及驗收目標，**不包含**內部正式報價、完整本機報告、球團文件、球員原始資料、未公開演算法或正式 ABS 判決功能。

## v3.1：自研／成品兩版與成本查核

- A 自研量測：使用現成開放raw感測器，自研量測核心；不是15–22萬能從RF PCB到ASIC全部自製。B 成品應用：購買整機量測能力，自研授權adapter、分析與孿生，不假裝已取得L0/L1。
- 頂部版本切換會同時切換場景節點、階段說明、計畫/價格、直接旋轉驗收及流程。可分享 `#build/poc/plan`、`#buy/poc/plan`；舊版 `#poc/plan` 相容至A版。
- A版152,950–219,650的加總正確，但屬工程預留、不是達標總價。Basler與OPS243可查公開價；FLIR361美元只確認公開PDF索引，現價需重報；其餘配件尚缺逐項書面報價。
- B版列Rapsodo PRO 2.0投球/雙功能、PRO 3.0、TrackMan B1、FlightScope X3B；費用未知為null/待報價，三年數字只加已知訂閱，不冒充完整TCO。X3B套裝PC不重複計價。
- Rapsodo投捕間安裝與場內淨空衝突；B1公開feed為iPad結果後約3秒的目標，不是取樣→自製畫面800ms。沒有成品被標成全部需求已滿足。
- B版3D僅為B1後方場外概念，非原廠核准位置，不把不符合淨空的Rapsodo任意移位充數。切換保留人物半透明與投球設定；記錄另存 `solution_variant`，仍為合成資料。

完整金額、假設與原廠連結見[價格查核與成品版成本](docs/price-audit-and-buy-v31.md)。`procurement.js`為成本/版本單一來源，`procurement-ui.js`呈現B版與A版查核資訊。

## v3.0 重要變更

- 第一階段就包含 **2 顆球路＋2 顆球縫高速相機＋24GHz raw I/Q**，以及兩側補光、同步盒、PC 節點。轉速與三維有向轉軸直接量測是必要驗收，不以球路推估補洞。
- FPGA 與 60GHz ADC 改為明確的選配研究開關；不取代一期必要光學，也不默默算入免費升級。
- 延遲改為最早納入的感測取樣到本地畫面可見 **≤800ms**，含觀測窗、傳輸、運算與渲染。這是工程目標，Demo 不測量或承諾實際延遲。
- 新增「直接旋轉」「計畫 / 預算」「0.8秒流程」，球縫區與合成有向軸可切換。光學計算器依當前 S1/S2 位置估球像、拖影和可見幀數，ROI 不會放大球像。
- 同源 BOM 為 NT$152,950–219,650；10萬條件案增購目標87,600，須借足球路設備、照明與獨立參考儀；牛棚累計470,000；全場100萬是封頂研究配置，不保證完整OAA或正式ABS。
- 純合成的旋轉視覺化放在 `synthetic_spin`；`measurements.spin_rpm` / `spin_axis_world` 保持 `null`。不會把3D動畫誤標為量測成功。

公開頁可直接連到 `#poc/spin`、`#poc/plan`、`#poc/flow`。完整[公開計畫摘要](docs/open-sensor-plan-v3.md)與[資料契約](docs/data-contract-v1.md)另列於文件。


## 展示範圍

- 切換一期 PoC、牛棚驗證、局部擴充、全場構想四個情境；聚焦球縫/本壘只移動觀看鏡頭，不移除任何一期必要感測器。
- 點選節點查看用途與示意安裝位置；拖曳旋轉、縮放、切換視角。
- 草皮紋理、投手丘、五角本壘板、看台、護網、投捕手、設備支架與日夜光照；切換本壘／投手近景。
- 「投捕手半透明」一鍵淡化身體、球帽、手套及捕手護具；「過濾設定」可分別切換並調整 10%–60% 不透明度。場景切換保留設定，重新整理回到實體。
- 人物改為通用釋球／蹲捕姿態，附球衣號碼、接縫、面罩、護脛；球場新增草土表面細節、看台椅背、走道、欄杆、燈具與漸層天空。模型是程序化示意，未使用球員掃描或動作捕捉。
- 四種手選球路、可調身高、帶內／帶外／邊界／遮擋情境，3D 與 2D 進壘點共用同一筆模擬事件。
- 本機保留最近 60 筆模擬投球，JSON 包含場景/計畫world軌跡及合成旋轉，CSV 提供摘要。球種不是自動辨識，轉速/動畫軸是預設值，沒有硬體原始影像或 I/Q。另可下載公开BOM CSV與計畫JSON。
- 數據能力頁說明投打守、球種、旋轉、比賽事件和 ABS 所需的原始資料及設備。這是需求分類，並非已實作所有進階指標。
- 所有數字及覆蓋範圍皆為示意，並非量測或已驗證性能。未知指標為 `null`，不偽裝成量測結果。
- 網站是純靜態頁面；即時感測資料需另接授權後端，請勿在前端放入金鑰或球員個資。

## 維護

來源檔在 `src/`：`nodes.js` 為節點、`plan.js` 為共用預算/流程/來源、`optics.js` 為光學試算與座標轉換、`planning-ui.js` 為新分頁、`scene.js` 為場景、`pitch.js` 為模擬與判讀，`capabilities.js` 為資料需求。所有公開內容應先檢查不含內部正式報價、機密文件或個資。

安裝座標由 `deployment.js` 依階段覆寫；所有感測器、支架與機櫃均移至示意活動區外。可開啟「活動區界線」並在設備頁查看固定方式、觀測距離和移位取捨。詳見[場內淨空安裝方案](docs/perimeter-installation.md)。

人物由 `actors.js` 建立並按材質合併幾何以減少繪製次數，看台座椅以 instancing 重用。`actor-visibility.js` 隔離各人的材質，半透明時停用深度寫入與人物投影，恢復時還原原狀。此功能只改善觀看遮擋，**不代表實際感測器可穿透人體**，也不修改 ABS、球種、軌跡或匯出資料。

## 座標與判讀

公尺座標的原點為本壘後尖端，x 為捕手視角向右、y 向上、z 向捕手。本壘前緣 z = −0.4318 m，中間平面 z = −0.2159 m。這不是 Statcast 的座標軸，介接時需要明確轉換。

v3計畫的world座標為 x向右、y向投手、z向上，`world[x,y,z] → scene[x,z,−y]`。點擊設備可看兩套座標；匯出資料分欄存放，不直接交換y/z而漏掉符號。

示範好球帶採 MLB 2026 參考比例，並非 CPBL 規則。球心通過平面時，使用圓與矩形相交；以圓角矩形的 signed distance 避免角落誤判。12 mm 不確定度是**任意示範假設**，沒有信賴水準或量測驗證。邊界／失效進入 REVIEW；此演算法不是完整官方 ABS。身高輸入僅改變好球帶，場上人物為通用示意模型。

投球採固定加速度簡化模型，釋球速度由時間求根維持一致；不根據預設轉速推算 Magnus 或球縫作用。回放為慢動作，沒有量測端到端延遲。球上光暈為觀看輔助，實際幾何半徑仍為 3.66 cm。

## 驗證

`npm test` 驗證球路、半透明材質、全部主案/選配的場內淨空、BOM與800ms加總、ROI/曝光/視野試算、座標往返、合成與實測欄位分離。`npm run build` 建置網站。Playwright 的 `tests/browser-smoke.mjs` 檢查四階段、六分頁、光學試算、選配開關、逐球記錄、四種下載及手機版（使用 Edge；可透過 `PLAYWRIGHT_MODULE` 指定模組路徑，`DEMO_URL` 指定本地或公開網址）。
